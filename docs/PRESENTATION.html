Asset Intelligence Copilot

Evidence-Grounded Chat Assistant for Oil Well Operations

Hacktoberfest 2026 · FlytBase Hack Day

FastAPI • DuckDB • React + Vite • OpenRouter (optional)

Problem Statement

  • Data: 200 wells, inspections, maintenance, regulatory, notes, manuals & SOPs
  • Need: Plain-English answers with citations & evidence
  • Must: Deterministic arithmetic, two-level memory, honest about conflicts
  • Goal: Work on unseen test dataset with generative UI

Solution Overview

Backend

  • FastAPI + DuckDB
  • Semantic views apply corrections
  • Structured ToolResult
  • Optional cached LLM (re-parse only)

Frontend

  • React + Vite (TS)
  • card/table/line/bar/map/heatmap
  • Evidence + conflict cards
  • Pure SVG

Data Layer

  • Single DuckDB file
  • v_prod_status, v_downtime, v_spills, v_inspection_resolved, v_rule_effective
  • Assertions + report_facts

Why DuckDB?

Correctness

  • All arithmetic in SQL
  • Corrections in views
  • Single source of truth
  • Deterministic

Speed & Simplicity

  • In-process, zero-ops
  • ~40k rows – instant
  • Rebuild via COPILOT_DATA_DIR

Domain Logic

  • Downtime = 7d per not-producing
  • Thresholds from extracted rules
  • Spill class/reportability in views

80/80 checks passed (scenarios + tools)

Memory, Conflicts & Corrections

Two-Level Memory

  • Shared: well-scope visible to all
  • Private: "wells we discussed" per user

Corrections

  • Inspection-scope → propagate
  • Well-type overrides → scoped
  • Applied inside views

Honest Conflicts

  • Claim vs data surfaced
  • Unconfirmed if contradicting
  • Consequences explained

Complex Queries – How Solved

  • Multi-source: Inspections • Maintenance • Notes • report_facts • Regulatory • Docs • Rules
  • Windows: "last 90d", "last 13 weeks", "2025"
  • Compliance/RCA: SR-01/02/03, RC-03/04 from computed state
  • Visuals: SQL aggregates → SVG (card/table/line/bar/map/heatmap)
  • Propagation: Corrections recompute reportability & obligations

Takeaway

  • Compute, don't guess – SQL only; LLM thin + cached
  • Views = consistency – logic centralized
  • Evidence-grounded – cites record IDs
  • Honest & scoped – conflicts surfaced, memory correct
  • Fast & portable – in-process, no API key needed
  • Proven – 80/80 deterministic checks
